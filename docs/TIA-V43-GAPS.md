# DeskBox V4.3 TIA 编程差距清单

源码基线为 `b46b2b6`。此前发布的 `4.2.2-ui.11` 已验证安装、100%／125%／150% DPI 和导出资料工作台。实际工程闭环需要许可有效的 Siemens TIA Portal V20、Openness 用户权限和经授权的独立 `.ap20`。开发工作区为 Linux，Windows CI 的历史环境报告未发现 V20 PublicAPI。 [安装版验收](TIA-INSTALLED-UI-REVIEW.md) · [原生能力验收记录](TIA-V422-ACCEPTANCE.md)

| 项目 | 基线现状 | V4.3 处理顺序 |
| --- | --- | --- |
| 工程与目标 PLC | 已支持读取导出资料及尝试只读打开 `.ap20` 离线副本。PLC 下拉位于验证页，工程来源、CPU、选中对象和工作模式分散显示。 | 第一阶段加入明确的来源、路径、CPU、目标对象与能力确认。任务固定记录目标，重绑时废止旧审批。 |
| 多 PLC 与对象范围 | 原生快照保存控制器路径，部分导出对象缺少明确归属。加载资料和切换对象仍使用页面即时状态。 | 第一阶段只用有来源的候选范围，多个 PLC 需明确选择。缺少归属时限制为草稿或分析。 |
| 归档与旧版 | V20 连接器只接受独立 `.ap20`。AML、SimaticML、SCL/UDT/DB 和 IO CSV 使用独立只读解析。 | 第一阶段识别归档并描述恢复要求。实际恢复、版本兼容性和原生入口分别验证。 |
| AI 实际生成 | 已可接收并验证结构化单块 SCL。关键字段缺失时可能只收到 `PLAN`，暂无独立可追踪任务、明确截止时间或一键隔离草稿路径。 | 第二阶段优先真实生成，有限时、明确阻塞和可手动请求隔离草稿。有正文时落盘 `.scl`、静态检查报告和补丁。 |
| 任务日志和恢复 | 工作台显示通用进度和本次操作日志。Openness 作业有独立回执，模型任务及审查步骤缺少持久记录。 | 第一、二阶段建立任务 ID、时序、记录文件、错误、当前状态及下一步。重开任务核对工程及 CPU，恢复草稿与证据。 |
| 离线写入 | 已有严格的单个全新 ASCII FB 专项入口，绑定源哈希和 CPU，通过审批后在另一份独立副本尝试导入、编译、复读与保存。 | 第一阶段将现有入口约束到已确认目标。已有块替换、原生 FC/DB/UDT、新工程恢复和硬件修改仍需第三至第五阶段逐项验证。 |
| TIA 实际编译 | 实现调用 `ICompilable.Compile` 并解析 Siemens 回执。当前真实环境与工程 **BLOCKED**。 | 第四阶段在持证主机提供实际调用日志和编译结果。本阶段保留原入口及限制。 |
| LAD/FBD 与工程安全 | 已可读取已导出的结构、符号和有来源的连线。线上下载、变量强制和设备操作没有 AI 入口。 | 本阶段继续只读分析，已有安全联锁或生产设备逻辑保留独立人工审查。原生 LAD/FBD 写入待第五阶段确认能力。 |
| IDE 回归 | 已有原生编辑器、分栏、只读来源、诊断定位和草稿双栏差异。多文档编辑及工程对象双栏仍不足。 | 前两个阶段复用原页面，集中补充目标和任务区域。完整编辑器及 UI 回归留到相应阶段。 |

第一、二阶段验收以真实安装版、本机可编辑 SCL 文件、归属检查、任务记录和静态诊断为证据。测试资料和测试模型均注明来源。未经实际授权环境运行的原生读取、写入和编译标记为 BLOCKED。
