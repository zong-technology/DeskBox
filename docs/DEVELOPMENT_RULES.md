# 通用软件开发规范 V2.0

## 质量与执行

以功能完整性、质量、稳定性、安全性和用户体验为先。除非用户明确要求仅分析，在授权范围内完成实际实施、测试和验证。优先解决根因，复用成熟实现和测试。禁止虚假实现、合成数据冒充真实客户数据、伪造验收、无效入口及假完成。对常规技术选择自主推进，必要授权、不可逆操作或重大范围变化须由用户决定。

标准顺序为需求理解 → 状态核对 → 影响分析 → 调度 → 实施 → 测试 → 验证 → 更新文档 → Git 提交。开始时确认受影响入口、现有行为、兼容性和数据边界，结束时区分实测结果、剩余事项与阻塞原因。

## 模型、推理与智能体

| 任务 | 当前环境可用时的选择 |
| --- | --- |
| 简单改动与核对 | 低推理 |
| 常规开发 | 中等推理 |
| 核心功能、跨模块缺陷或复杂故障 | 高推理 |
| 关键架构、安全审查、复杂正式版验收 | 根据风险选择可用的最高等级 |

默认单智能体。独立工作可以明显并行或需要独立复核时才委派，明确文件归属、输入和交付，避免重复分析和覆盖改动。已有模型或推理不足时，按权限升级并重新核验重要结论。只使用会话实际开放的调度能力，配置时遵守宿主允许的模型和理由。会话支持子智能体委派时可以使用，主会话切换、自动选模和推理覆盖以宿主实际开放的设置为准。没有相应能力时继续使用当前配置并保持验证标准。

## 按需读取与实施

从 `AGENTS.md` 和项目状态开始，按需读取接口、源码和现有测试。优先使用路径与符号搜索，复用已核实且未变化的信息。按问题范围修复，避免大型无关重构、重复审查和冗长汇报。必要测试、安全检查和运行验证应保留足够资源。

模块应高内聚、低耦合。UI 负责输入与展示，应用服务负责用例，领域层负责规则，存储和通信通过各自接口处理。复用现有类型、命名、日志和异常表达方式，避免不必要的依赖或硬编码。处理存量数据、兼容性、失败重试、取消、并发冲突与恢复。新增组件优先可独立测试。

## UI 与 UX

延续项目适用的视觉和交互规范，布局清晰、控件可操作，按需要支持主题、缩放和不同分辨率。动画应服务操作，并受性能约束。功能入口要接到真实数据及服务，处理等待、空数据、失败、取消和完成。窗口改动尽可能运行并截图，记录检查的窗口、分辨率、缩放和未覆盖项。DeskBox 各阶段的视觉投入遵循根目录规则和路线。

## 安全、数据和权限

默认最小权限。保护密钥、密码、内部配置及客户资料。数据外发需要明确授权，产物与日志对外前检查敏感内容。不可逆操作先确认。重要数据变更设计备份与恢复，异常恢复使用独立副本验证。工业系统默认离线及只读，任何进一步操作受项目授权、隔离环境和安全边界约束。

## 验收与 Git

按风险做单元、集成、回归、性能和安全测试，并经真实业务入口验证。记录运行环境与测试数据类型、源码 SHA、操作结果、失败及阻塞。编译是构建检查，正式验收还需要覆盖相关实际行为。发布记录包含构建、来源、测试证据与可校验产物。

确认工作区、分支和远端状态，保留用户改动，提交信息说明变更内容。提交、推送和 PR 受用户授权约束。禁止擅自强推或破坏历史。重要任务完成后更新项目状态、技术决策、测试结果与后续事项，版本变化写入变更记录。默认以中文简明汇报成果、修改范围、实测结果、已知问题、后续计划与远端同步情况。
