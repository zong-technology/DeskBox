# DeskBox V5 分阶段开发

本轮采用功能优先、UI 后置安排。各阶段先落实数据、权限、服务和业务验收。维持可操作的现有界面，保留 Windows 构建和版本回退。

| 版本 | 工程范围 | 进入后续阶段的依据 |
| --- | --- | --- |
| alpha.1 | 最新开发基线、工程上下文、项目隔离、导航、内置 TIA MCP | 项目切换、旧数据保留及 Windows 运行验证已有证据。 |
| alpha.2 | 桌面 Agent Runtime、通用 MCP、六层边界、设计交接 | 可独立测试的业务服务，真实模型协议、第三方服务握手、权限、取消、回执、恢复与 Windows 回归。 |
| alpha.3 | PLC 工程只读、DeltaV 离线结构化分析、统一 Tag 和跨模块稳定 ID | 授权 V20 工程与 FHX 验收分开记录，完成 Tag CSV／Excel 映射、验证、版本差异及项目归属。 |
| alpha.4 | 制药验证、风险、URS/FS/DS 至 RTM、测试证据、偏差和报告草稿 | 需求到证据的真实关系、用户审核、原件哈希与验收报告。 |
| alpha.5 | 仪表资产、通信资料、PI/UFL、工程知识、截图、项目工作效率 | 在授权资料上展示读取、索引、来源、证据关联、导出与恢复。 |
| alpha.6 | 自动化业务引擎、智能桌面、移动离线协同 | 触发、任务历史、撤销、离线队列与同步冲突证据。 |
| beta.1 | 功能与接口冻结，验收和 UI 资料交接 | 收敛设备和 UI 风险，梳理全部功能入口、接口与项目边界。 |
| beta.2 | 集中重构界面和高阶布局 | 覆盖确认流程、可访问性、多屏、分辨率和 DPI，回归既有工程业务。 |
| RC | Windows 安装升级、联合工程验收、恢复及回滚 | 带原始日志、授权环境证据及明确的剩余问题。 |
| V5.0 | 签名及正式发布 | 版本身份、校验、发布说明与可回退安装包。 |

后续阶段分别记录受控协议测试、Windows 运行以及真实工程环境。持证 V20、授权工程或实际导出物缺失时，独立开发可测试路径并保留现场阻塞状态。

## alpha.4 工程交付顺序

1. 以项目 ID、稳定 TagId、来源文件哈希及原文位置建立验证资料引用。仪表暂保留稳定关联接口，资产台账继续按阶段推进。
2. 落地 URS、FS、DS 至 DQ、FAT/SAT、IQ/OQ/PQ 的需求、测试用例与证据实体。逐项记录关联、版本、覆盖、实际结果和待审核状态。
3. 加入原始证据哈希和不可覆盖归档。通过可重现用例覆盖偏差、CAPA、Punch List、修改、审核、撤回和数据恢复。
4. 由真实需求、证据与状态导出 RTM、Excel 和 Word 报告草稿。应用日志保留工程诊断用途，签核与审计有明确权限和验收边界。
5. 继续保留独立数据、接口和原生 Windows 安装回退证据。持证 TIA、授权 FHX 样本等现场验收与功能开发并行记录。
