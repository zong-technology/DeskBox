## 产品定位与现有项目保护

DeskBox 是独立的智能桌面、工作管理及专业工程辅助平台。每项核心业务保留完整的人工操作路径。用户可以在 DeskBox 内选择项目、录入资料、执行操作、审核、查看结果和处理失败。ECO 智能管家未来可作为可选调用方。缺少 ECO 服务、配置、凭证或网络时，DeskBox 的本地业务和人工工作流仍应可用。

实施前核对源码、分支、技术栈、数据格式、实际开发状态和受影响入口。保留已经验证的功能及用户数据，优先修复实际使用问题。沿用 WinForms / .NET Framework 4.8 和现有数据格式。重大变更须说明必要性、兼容及迁移影响，明确备份、验证和回退，并取得适用授权。 [架构](ARCHITECTURE.md) · [版本证据](V5-BUILD-PROVENANCE.md)

## UI 与 UX

采用专业、克制的科技风格，突出操作状态、数据层级及常用入口。按工作场景安排信息密度与空间，减少重复录入和页面跳转。深浅色及随系统切换作为适应性目标，结合现有主题、缩放与实际屏幕验收推进。操作入口应调用真实业务服务，并呈现等待、空数据、错误、取消和结果。当前 V5 功能优先，及时修复阻碍操作的问题，集中视觉和布局重构留到 beta。 [UI 交接](UI-HANDOFF/PRODUCT-OVERVIEW.md) · [V5 开发路线](V5-DEVELOPMENT-ROADMAP.md)

## ECO 可选调用与联合验证

- 新增核心业务时，把适合对外开放的操作放在可独立测试的服务中。人工入口和未来适配器共用业务规则、权限及结果。DeskBox 自行管理应用生命周期、用户数据和项目上下文。禁止直接依赖 ECO 数据库或其内部实现。
- 预留服务发现、能力注册与查询、项目及文件查询、任务创建与执行、运行取消与进度、执行结果、事件通知、权限及审计。启动和人工操作不以 ECO 在线作为前置条件。具体公开能力随需求逐项确定。
- 当前优先完善 DeskBox 本身。用模拟客户端、合成资料和接口契约测试验证实际服务及边界。真实 ECO 联调需单独授权和验收。新增或修改公开接口时更新参数、错误、版本兼容性及迁移说明。 [现有能力、缺口与接入顺序](INTERFACE_SPEC.md#eco-接入准备评估)

## 安全与记录

默认最小权限，在 DeskBox 服务侧按调用者、项目、动作、文件范围和数据外发授权校验。工程资料默认本地，外部模型或其他第三方读取需独立授权。重要文件变更先确认并具备备份恢复。生产系统默认只读，禁止未经授权的设备控制，禁止向 ECO 开放生产写入、下载、强制、切换运行状态或修改安全联锁。重要外部调用应记录调用者、项目、能力、关联请求或运行 ID、结果和时间，避免把密钥或敏感工程正文写入日志。验证审批和证据遵守既有人员权限与原件保护要求。
