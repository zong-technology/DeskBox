# 用户流程

## 工程问答与本地工具

1. 选择项目，打开工程会话。若要用外部模型，核对项目外部 AI 开关和 AI 环境。
2. 选模型并发送。文件内容按当前工程及附件授权范围读取。
3. 查看回答、工程工具结果并按需确认受保护操作。模型、工具、模型的步骤各自保留状态。
4. 查看「执行记录」定位步骤。取消或换项目后，旧回复和回执仍属于原项目。
5. 无模型或明确使用本地模式时，按文件名检索或输入工程计算命令。

## 第三方 MCP

1. 在要使用服务的项目中打开「MCP 管理 → 第三方 MCP」。
2. 填写服务注册，确认其提供者和数据范围，再启用服务。
3. 如服务需要，输入当前窗口临时令牌。运行检测并从真实目录选择工具。
4. 对照工具文档与 Schema，授权只读工具。输入 JSON 参数并再次确认单次调用。
5. 检查真实响应、耗时和是否已尝试发送。断线后先核对服务端状态，再决定下一次操作。
6. 服务调整时重新探测。Schema 或服务器身份变化需重新确认授权。需要停止所有调用时停用注册。

## 模型能力与本机 TIA

1. 在系统设置选择已保存服务商，运行普通连接测试或文本流检测。
2. 在 PLC Studio 查看当前工程、导出资料或经批准的离线作业。MCP 管理页的本机检测用于确认私有进程协议。
3. 真实工程接入前核对 Siemens 证书、TIA 版本、Windows 用户权限和工程授权。

## 工程资料与统一 Tag

1. 在项目中心选择项目，经项目上下文、PLC 变量页或 DCS 进入工程资料。
2. 打开离线文档，选择对象并查看来源位置、字段和诊断。选择两个版本运行比较，需要时保存差异 JSON。
3. 表格侧确认字段映射、工作表和系统名。浏览预览，选择仅追加来源或确认替换已映射字段。
4. 在 Tag 台账查询、编辑或比较历史，按来源跳回原文件。备份恢复在确认后保留坏文件。
5. 在 AI 中授权文件，再要求对比。第三方工具先由操作者核对本机服务和 Schema，允许后由模型申请，实际调用逐次确认。

## alpha.4 验证流程

1. 选择项目，进入验证工作台。配置适用阶段，登记受控文件编号、版本以及来源。
2. 录入或导入需求和测试用例。核对原文和映射后再保存。将需求、设计、风险、用例和 Tag 用实际 IDs 关联。
3. 执行测试并录入实际结果，添加原始证据。失败时创建偏差并记录评估、调查、处置和重测。授权人员录入审核决定。
4. 在 RTM 核查覆盖、未提供来源、缺失证据和开放偏差。处理报告中的不完整项。
5. 比较两版工程资料并记录待评估影响。如果需要重新测试，由授权人员确定。
6. 建立验证基线并检查交付资料。导出 XLSX RTM 与 DOCX 草稿，检查旧修订、证据和引用是否还能回查。
