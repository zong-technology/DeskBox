# DeskBox 5.0.0-alpha.4 制药验证工作指南

## 工作路径

| 工作 | 记录方式 |
| --- | --- |
| 配置项目和阶段 | 在工程工作区选择当前项目，从「验证中心 → 打开验证工作台」按项目管理阶段和资料。阶段计划进度继续沿用既有 ValidationProgress，业务统计从需求、执行、审核、证据和交付记录分别计算。 |
| 录入和修订需求 | 手工录入，或从 Excel、CSV 和 Word 生成待确认预览。核对文档编号、文档版本、需求编号、风险、适用性与来源位置。每次修改保留历史版本。 |
| 建立追溯 | 在需求、设计、风险、测试、证据、偏差和审核之间关联实际记录 ID。工程 Tag 引用同一项目的 TagId。使用 RTM 检查未覆盖、无来源、缺失证据及开放偏差。 |
| 记录测试 | 先定义测试方案、用例、步骤和预期结果。执行时由操作者记录人员、时间和实际结果。重新测试单独建立执行记录，可回查原用例修订和前一次执行。 |
| 归档证据 | 将获授权的文件按验证记录归档并校验 SHA-256。保留原始证据记录。裁剪、标注或脱敏文件作为独立衍生件记录，可追溯其原件。 |
| 处理问题 | 建立失败测试的偏差，记录调查、处置、风险、重新测试及审核。CAPA 与 Punch List 通过实体关联引用已有记录。 |
| 评估变更 | 使用两版工程资料和确定性差异识别候选影响。按实际关联追到需求、用例、证据与风险，再由人员决定重新测试范围。 |
| 报告与基线 | 整理实际台账和追溯记录，保存基线和必要的报告草稿。导出后检查缺项、状态、来源和版本。 |

## 工程记录和审核边界

- 稳定 ID 用于项目边界、关联和历史。人员阅读的需求编号、阶段名、测试编号及附件名保留作业务标识。
- 执行状态、业务审核、原件完整性和交付状态分别呈现。通过或失败来自人工记录的实际结果，审核决定使用其独立记录。
- 软件提供工程工作记录、应用运行日志、业务修订历史和人工审核记录。正式电子签名、受监管审计追踪及部署验证需另行建立。
- 文件哈希可检测字节变化。应用内防覆盖和独立衍生件用于保留归档来源，存储访问控制、备份保护和正式验证由部署环境管理。
- 面向 GAMP 5、21 CFR Part 11、EU GMP Annex 11、ALCOA+、权限、审计追踪和恢复的资料应记载依据版本、适用性、来源及人工复核。资料用途为项目验证辅助。
- AI 验证查询只读取当前项目记录，仅开放本机数值回环模型。无需模型时可用「工具」发起本地确定性查询。返回验证数据的会话不能切换到外部模型继续携带这段历史。实际执行、审核、偏差关闭和正式报告均由人员决定。

## 导入、对比和报告

- Excel 和 CSV 导入使用表头及确认后的字段列。选择工作表后预览行与位置，处理冲突后再入库。Excel 资料应提供静态单元格值。
- DOCX 正文可从形如「URS-001：需求原文」的编号段落生成候选，或选择正文表格进行字段映射。核对候选编号、描述、段落或表格行位置、来源哈希及文档版本后确认。
- 第二次导入同一阶段、同一逻辑文档的新版时，预览列出新增、删除和修改。确认应用修订后保留既有需求 ID。完整表格可选择作废新版已移除的需求，Word 候选仅用于新增及修订。正式台账可对比同一需求的历史修订。
- 导出时选择新文件名，并检查报告类型、适用范围、审核状态、证据、缺项及引用。企业 DOCX 模板在正文独立段落写入 `{{Body}}` 或指定等效映射，可另用项目名、阶段、报告名和快照标识等字段。模板须为无宏 DOCX 且不能含外部关系。生成器保留模板原件。
- 比较工程变更时保留前后来源文件、版本、哈希及实际差异。可按稳定 TagId 或可核对来源定位影响对象。名称相同或相似的候选需要另行核对。已经执行或审核的历史记录继续可查。

## 持久化和恢复

验证记录保存在应用数据位置内的 `validation/` 项目目录中。台账记录 Schema 版本、快照校验值和修订历史，证据原件在项目库内独立保存。并发变更或导入源变化后须重新读取。主台账可用备份恢复时，先复核只读备份，再明确执行恢复；复核后检查相关归档的哈希。系统设置的数据备份会在项目写锁下核验并复制验证台账和证据。整站恢复前检查备份并保存恢复前快照，先准备归档字节，再发布对应项目台账。版本回退演练应使用备份副本和单独的用户数据位置。

## 审核、测试与偏差

创建首个验证计划时，程序记录当前 Windows 账户为计划所有者。仅该账户可编辑计划和审批名单。允许参审的账户使用操作系统身份，通常填 `域名\用户名` 或 `计算机名\用户名`。审核须选择批准或驳回并填写意见，绑定到具体修订。资料有新修订时，验收该修订需要新的审核记录。业务人员名称和报告内容应来自真实记录。

执行中的记录可补录步骤实际值并结束。用例若含多个步骤，测试通过前需要提交每步实际结果。终态保留，撤回须填写原因。重测选择同一用例的既有结束记录，另行记录新结果。偏差关闭要求状态为待审核、当版已批准，并填写影响、根本原因和处置。如果已指定重测，其状态须为通过。关闭生成新修订，同时保存关闭所依据的审核记录 ID。

证据需位于当前项目范围，归档先核对来源并复制内容，再保存证据记录。相同项目内相同字节共用一份内容，仍各自保留稳定 ID、原始来源和测试关联。衍生材料和原件需保持同一测试范围。单个证据文件上限为 512 MiB，归档文件的体积和 SHA-256 可通过验证操作复核。批准证据时会再次校验实际归档。归档缺失或损坏时，从「证据库 → 恢复证据」选用当前项目内的原件副本，只有大小和 SHA-256 与原归档一致时才恢复内容。损坏副本保留供核查，证据 ID、原关联和历史保持不变。
