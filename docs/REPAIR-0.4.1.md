# 0.4.1：同步、Win+F 与 AI 应用管理修复

## 现场事件双向不同步

实际排查发现：电脑数据目录没有云登录凭证，云端也没有主电脑授权；此前的“ONLINE”仅表示局域网服务开启。手机的3条提交停在云端等待电脑处理。

已通过当前账号的 Cloudflare 管理授权补齐缺失的主电脑设备，凭证仅以 Windows DPAPI 密文保存到原数据目录。修复前已备份任务、配置、同步记录和冲突历史。

随后发现手机离线连续编辑同一事件，会产生同一源版本的多个提交，被错误当成不同端并发修改。现已修复：

- 云端合并同一手机、同一记录、同一源版本的未确认修订，保留最新草稿；迟到旧稿不会覆盖新稿。
- 电脑记录原始提交版本和时间，将同源后续编辑提升为递增的服务版本；元数据由接收端生成，客户端不能伪造。
- 另一台设备的编辑、电脑实际修改和不同基线继续执行冲突保护。
- 已存在的同源伪冲突按因果条件重新处理，原始记录和处理历史保留。
- 状态栏及手机联动页明确分开 LAN 与 CLOUD；未登录电脑不会再仅凭局域网在线显示云同步可用。

真实数据复查：云端和电脑各有2条现场事件，另有3个项目和14项任务；3条手机提交均已确认，待处理冲突为0。手机打开应用进入前台后会按原自动同步规则拉取；未替代真实手机屏幕验收。

## Win+F 呼出

Win+F呼出当前软件窗口，Ctrl+Alt+Space继续保留命令中心入口。本机Win+F常规注册返回1409（被系统占用），已提供仅针对该组合键的键盘钩子回退，避免按住F连续重复呼出，并处理Win键释放的开始菜单干扰。
快捷键逻辑及钩子注册测试通过，真实物理组合键体验仍需使用者验证。

## AI 能力接入

- `task.list/update`：真实任务列表、筛选、修改和完成状态，更新前检查读取校验值。
- `project.list`：项目目录、进度和按需读取的验证节点。
- `incident.list/update`：现场事件和处理措施，保留版本及关闭校验。
- `app.context/navigate`、`workflow.list`：应用状态、云连接状态、页面跳转和工作流读取；原工作流执行工具继续保留确认。
- 应用内部任务/项目读取不依赖文件访问开关。应用数据操作在UI线程调度，文件解析继续在后台执行。
- `fs.list/move/copy/rename/trash/undo`：授权范围内的文件管理，复用现有不覆盖和可撤销文件服务。
- `doc.edit`：DOCX文本片段、XLSX字符串和UTF-8文本的定点替换；先读SHA256，检查旧版本并备份。其他Office压缩部件原样复制，验证了兼容命名空间、公式及其他二进制部件保留。
- 文本覆盖写入增加原件备份和原子替换；搜索跳过无授权/重解析路径，允许取消，并有15秒范围限制。

不支持的能力不会冒充已实现：PDF原位排版改写、旧DOC/XLS/VSD及Visio图形编辑仍待扩展；复杂Office版式仍需真实打开复核。读写受当前授权目录约束，修改、移动和删除仍需操作确认。
