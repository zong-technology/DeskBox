你目前的 DeskBox 已经具备比较完整的功能模块，但从截图来看，主要问题不是功能数量不足，而是页面视觉层次、空间利用率、信息密度、组件设计、交互反馈和页面统一性还没有达到成熟商业软件的水平。

我建议不要简单地让 Codex 把按钮变漂亮，而是要求它按照专业工业软件、现代 IDE 和高端 AI 工作台的设计标准，对全部 12 个页面进行一次完整的 UI/UX 重构。

下面这份可以直接交给 Codex 或 DeepSeek Harness 作为最终设计与开发要求。

# DeskBox V3.0 — 全站 UI/UX 深度重构设计与实施规格书

## 一、项目总体目标

对现有 DeskBox 全部 12 个页面进行全面视觉升级和交互体验重构。

本次不是简单换肤，而是一次完整的产品级 UI 改造。

最终效果参考：

- 专业级工业自动化工程软件。
- 高端 AI 桌面工作站。
- 现代化开发工具 IDE。
- 高级数据监控与指挥中心。
- 高质量 SaaS 产品控制台。

核心要求：

1. 高科技感：具有明显的科技视觉识别度，但不能过度炫光。
2. 简洁：减少无意义的边框、空白和重复信息。
3. 信息丰富：合理利用 1920×1080 屏幕，不要出现大片无内容区域。
4. 专业：所有页面必须具有成熟商业软件的完成度。
5. 统一：12 个页面使用同一套设计系统。
6. 实用：不能为了视觉效果牺牲原有功能。
7. 动态：合理使用过渡动画、数据变化动画、悬浮反馈和状态指示。
8. 易读：中文、英文、数字、工程参数必须清晰。

特别强调：

不能只优化首页，必须逐页优化全部 12 个页面。

不能只制作静态效果图，必须将设计真正落实到现有软件中。

# 二、全局设计系统

## 2.1 整体视觉风格

采用：

Dark Industrial Futuristic + Premium Glassmorphism + Minimal Neon。

整体以深海军蓝、石墨黑为主，搭配青色、蓝色和少量紫色作为强调色。

建议颜色：

| 用途    | 颜色                     |
| ----- | ---------------------- |
| 主背景   | #080F1C                |
| 次级背景  | #0D1727                |
| 一级卡片  | #111E31                |
| 二级卡片  | #16243A                |
| 主强调色  | #32DDF5                |
| 次强调色  | #438EFF                |
| AI强调色 | #A78BFA                |
| 成功状态  | #20D6A2                |
| 警告状态  | #F5B942                |
| 错误状态  | #FF6474                |
| 主要文字  | #EDF5FF                |
| 次要文字  | #8DA3BF                |
| 辅助文字  | #637A99                |
| 分割线   | rgba(115,160,210,0.15) |

避免：

- 大面积纯黑。
- 大面积纯蓝。
- 过多彩色边框。
- 所有卡片都使用强烈发光。
- 过度使用渐变。
- 过度使用玻璃模糊。

## 2.2 布局规范

以 1920×1080 分辨率作为主要设计基准。

全局结构：

- 左侧导航栏：190–210px。
- 顶部工具栏：60–68px。
- 主内容区：自适应剩余空间。
- 页面内容边距：20–24px。
- 卡片间距：14–18px。
- 卡片圆角：10–14px。

要求：

- 页面不能出现无意义的大片空白。
- 主要信息必须在首屏合理呈现。
- 长列表使用内部滚动。
- 重要操作按钮放置在容易发现的位置。
- 页面之间不能出现不同的边距和组件尺寸。
- 支持窗口缩放和不同分辨率。

## 2.3 字体规范

中文优先使用：\
Microsoft YaHei / Noto Sans SC。

英文优先使用：\
Inter / Segoe UI。

字号：

| 类型    | 字号      |
| ----- | ------- |
| 页面主标题 | 22–26px |
| 页面副标题 | 12–13px |
| 卡片标题  | 15–17px |
| 正文    | 13–14px |
| 辅助说明  | 11–12px |
| 关键数据  | 24–36px |
| 表格正文  | 12–13px |

不要为了显示更多信息，把所有文字缩小到无法阅读。

## 2.4 全局组件

建立统一组件库：

1. Sidebar：左侧导航。
2. Topbar：顶部工具栏。
3. GlassCard：信息卡片。
4. MetricCard：数据指标卡片。
5. ProgressRing：圆形进度。
6. ProgressBar：横向进度。
7. StatusBadge：状态标签。
8. DataTable：专业数据表格。
9. SearchInput：搜索框。
10. FilterBar：筛选栏。
11. Modal：弹窗。
12. Drawer：侧边抽屉。
13. Toast：操作反馈。
14. EmptyState：空状态。
15. LoadingState：加载状态。
16. ConfirmDialog：危险操作确认框。

所有页面尽量复用这些组件，禁止每个页面单独设计一套风格。

# 四、动画和交互规范

整体动画必须高级、克制、流畅。

### 1. 页面切换

- 页面淡入。
- 内容轻微位移。
- 导航选中状态平滑过渡。

### 2. 卡片交互

- 鼠标悬停轻微上浮。
- 边框亮度适度变化。
- 图标轻微动态反馈。

### 3. 数据动画

- 进度环动态加载。
- 进度条平滑变化。
- 数据更新过渡。
- 运行状态指示灯。

### 4. AI交互

- 流式输出。
- 思考状态。
- 代码块加载。
- 消息操作反馈。

### 5. 自动化

- 节点运行动画。
- 节点连接线动态效果。
- 执行成功和失败状态。

动画时间建议：

- 普通交互：150–220ms。
- 卡片过渡：200–280ms。
- 页面切换：220–320ms。

提供关闭动画的选项。

# 五、工程实施要求

这是本次改造最重要的部分。

不能为了达到效果图而破坏现有软件。

开发前必须：

1. 完整检查现有源码。
2. 确认前端技术栈。
3. 确认所有页面入口。
4. 确认现有数据结构。
5. 确认所有按钮对应的真实功能。
6. 确认本地数据库。
7. 确认文件系统接口。
8. 确认AI服务接口。
9. 确认移动同步机制。
10. 建立现有功能清单。

开发原则：

- 优先重构CSS、布局和公共组件。
- 保留现有业务逻辑。
- 不随意修改数据库结构。
- 不删除现有功能。
- 不用虚假数据代替真实数据。
- 不允许按钮只有视觉效果而没有功能。
- 不允许只完成首页。
- 不允许使用静态图片代替实际界面。
- 所有页面必须适配真实数据。

如果需要修改底层逻辑，必须先分析影响范围，并保留数据迁移和回滚方案。
