## P1-B slice 2 — Shell thumbnail service (done 2026-10-31)

Implemented:

- `src/Shell/ShellThumbnailService.cs`
  - `IThumbnailService` abstraction: `Request` / `TryPeek` / `TryDraw` / `Prune` / `Clear` / `Stats` / `Ready` event.
  - `ThumbnailPolicy`: images, PDF, Office and video use previews; folders and shortcuts keep their real Shell icons to avoid slow handlers and blank placeholders.
  - Real acquisition through `IShellItemImageFactory::GetImage` (`SHCreateItemFromParsingName`) for supported preview types.
  - `HBITMAP` → 32bpp ARGB `Bitmap` conversion through `GetDIBits`, alpha preserved (fully transparent results are repaired to opaque), no `Image.FromHbitmap` alpha loss.
  - Failure path always falls back to the existing `SHGetFileInfo` icon (`Win32.GetShellIcon`, with `SHGFI_USEFILEATTRIBUTES` when the file is gone or unreadable), and negative results are cached so a broken path is not retried in a loop.
  - Bounded background queue (single STA worker, `Monitor`-based, default 128 entries, overflow requests dropped instead of blocking) with per-request de-duplication.
  - UNC/mapped-network paths and Offline/Recall cloud placeholders are classified before any Shell call and return a type icon without network hydration.
  - Local extraction runs on short-lived STA threads with a timeout (default 8 s); at most two timed-out extraction threads may remain active.
  - Bounded LRU cache (default 240 entries and a 64 MP pixel budget), touched by both `TryPeek` and `TryDraw`, evicting and disposing `Bitmap`/`Icon` resources; `Dispose` drains the queue, releases every cached GDI object and is idempotent.
  - `ThumbnailStats` counters (requested, deduplicated, dropped, extracted, fallback, failed, cache hits, evictions, timeouts, unsafe skips, active/peak extractor threads, pending, cached).
- `src/UI/IconBoard.cs`
  - Thumbnails only when `BoardView.Grid` and `IconSize >= ThumbnailPolicy.MinIconSize` (64); List/Compact keep the lightweight icon path.
  - `Thumbnails` property injection (the board never owns the service); real Shell icons remain visible while previews are pending, then update without blank tiles.
  - `Ready` notifications arrive on a worker thread and are marshalled with `BeginInvoke`; the handler checks `IsDisposed`/`IsHandleCreated` and swallows `ObjectDisposedException`/`InvalidOperationException`.
  - Own `Icon` cache is disposed on `Dispose`, and the `Ready` subscription is removed there.
- `src/UI/MainForm.cs`: owns one `ShellThumbnailService`, injects it into `IconBoard`, and disposes it in `OnFormClosing`.
- `src/Native/Win32.cs`: `GetShellIcon(path, large, useFileAttributes)` overload for the disk-free fallback icon (existing two-argument call sites unchanged).

Verification (`tools/thumbnail-accept.cs`, temporary sandbox only):

- DeepSeek candidate baseline: 37/37 assertions passed.
- Codex review expanded the suite to 43/43 assertions and fixed network/cloud short-circuiting, extractor-thread limits, empty-folder cache clearing and mtime version invalidation.
- Real PNGs are created in a unique temp folder; the service returns a genuine `Shell` thumbnail asynchronously (96×72 for a 512×384 source), never a fallback icon.
- `Request` returns in **0 ms** and duplicate requests are deduplicated; cache hits do not re-queue.
- Missing path falls back to a `SHGetFileInfo` icon without crashing and without retry storms; a permission-restricted path is reported as *skipped, file absent* on this machine.
- UNC path request does not block the caller and never enters Shell extraction; pending count stays bounded and timeout count remains zero.
- Offline/Recall cloud placeholders do not trigger hydration and use the type-icon fallback.
- Extractor-thread peak is hard-limited to two.
- LRU with capacity 2 evicts after 3 images (2 cached, 1 eviction).
- Grid paint queues only thumbnail candidates (2 of 3 items), List paint queues none; `Invalidated` fires after readiness and mtime changes invalidate/reload the thumbnail.
- `Dispose` clears the cache (4 → 0), rejects requests, makes `TryDraw` a no-op and tolerates a second `Dispose`.
- Regression after integration: Smart Desktop core **31/31**, Smart Desktop UI/Command Center **17/17**, V2 core **66/66**.

Known limitations:

- Thumbnails are decode-only: no persistent thumbnail disk cache, so a cold start re-extracts (bounded by the in-memory LRU).
- Office/PDF previews depend on the installed Shell handlers (Office/PDF IFilter or the `pdf` preview handler). Without a handler the Shell returns no thumbnail and the icon fallback is used by design.
- Mapped/UNC locations intentionally use Shell type icons rather than remote thumbnails in this phase.
- Local third-party Shell handlers can still time out; abandoned extractor threads are capped at two, and later requests safely fall back.
- Thumbnail staleness uses file mtime as a version key; in-place changes invalidate the old entry during `IconBoard.SetData`.
