# AI 对话可靠性修复

## 已定位原因

1. ChatService 的固定 30 秒看门狗无视流式活动，会中断正常长回复，并提前释放 Busy 状态。
2. 每个分片都 BeginInvoke 到 UI，随后重算全部历史消息高度；多轮长对话会积压绘制任务。
3. 聊天绘制中多处 SolidBrush 未释放。
4. Markdown 代码块的绘制高度比测量高度多 6 像素；列表/引用绘制添加前缀但测量未添加。
5. 工具结果及长代码行未按可用宽度换行。

## 修复

- 持续网络活动重置看门狗；包括 SSE 心跳和服务商推理进度。网络无活动阈值至少 120 秒，HTTP 层仍遵循服务商配置的超时。
- 看门狗只取消对应请求，等待工作线程清理后才释放 Busy，不会让旧请求取消新请求。
- 工具执行/等待确认不按网络空闲超时计算。
- 回答使用 StringBuilder 缓冲，约 50ms 发布快照；UI 80ms 合并处理最新快照。
- 消息高度按内容与宽度缓存；只绘制可见消息。释放聊天绘制使用的画刷，移除无流式时的光标刷新。
- 统一 Markdown 测量与绘制高度，长代码/工具内容换行，保留原文复制。
- 新增实际执行状态栏，显示等待响应、服务商生成、流式接收、已收字符数、工具执行、完成或失败。推理内容不作为回答冒充输出。
- 取消时保留已收内容；界面销毁时解除聊天事件并停止 UI 刷新计时器。

## 验证与边界

- 完整回归 27/27 套件、452/452 断言；随后扩展专项为 7/7（新增流式状态显示检查）。
- 独立专项包含 34 秒持续流：第 31 秒仍 Busy，最终有尾部分片39且无错误。
- 5 轮连续问答成功；主动取消恢复并保留内容；代码、列表、引用的测量与绘制高度一致。
- 截图：`shots/ai-reliability-review/streaming-state.png`。
- 测试使用本地 OpenAI 兼容 Mock，不等于真实厂商可用性验证。供应商侧缓存、代理缓冲、长度限制、网络中断和其超时设置仍可能影响响应。
- 应用中的推理/读取/工具状态仅基于实际收到的事件，不能显示服务商未提供的内部执行信息。
